# Navi v0.6.9

Tag: **`v0.6.9`** — annotated, pointing at the commit on `main` whose `reports/release-verification.json` records the run described below.
Package: `navi-interaction-bridge@0.6.9`, `AGPL-3.0-or-later`, publish configuration `access: public` with `--provenance` through keyless OIDC Trusted Publishing (`environment: release`, `id-token: write`, npm ≥ 11.5.1).

v0.6.8 left a lifecycle hole that every operator eventually met in their shell history: an interrupted pre-push hook killed its whole process tree, Playwright's `scripts/dev.mjs` webServer survived the kill re-parented to pid 1, and the next run — gate, suite, or `npm run dev` — stopped dead on `EADDRINUSE` for port 4174 before any meaningful output. v0.6.9 fixes the lifecycle rather than the symptom at two levels: the server now exits for real on `SIGTERM`/`SIGINT` instead of closing its socket and lingering, and it reclaims a *stale instance of itself* holding its port before binding, while a listener that is not this script is refused cleanly and left untouched.

## Why `reuseExistingServer` moved

The reclaim in `scripts/dev.mjs` was written first and tested first — and it did nothing for the repository's own gate, because Playwright probes the port with a raw TCP connect *before* it executes `command`, and refuses with "`http://127.0.0.1:4174` is already used" when `reuseExistingServer: false`. The hardening therefore had to reach the layer that fails. `reuseExistingServer: true` was the only honest move that does not weaken the suite: the server it would reuse is this same script reading the same fixture files that the current checkout built into `dist/`, so a reused orphan serves today's bytes; a server that is *not* this script still ends the run through the command's own refusal, which `tests/dev-server-lifecycle.spec.mjs` pins. The one weaker guarantee — something unrelated on 4174 answering the probe — is scoped to the suite's dedicated port, not a shared resource.

## Upgrading

```sh
npm i navi-interaction-bridge@0.6.9
```

No API, protocol, storage or page-shape change. The fix is about the process the suite launches, not about anything a tenant or an integration can observe. A self-hosted deployment picks it up by pulling/rebuilding `navi:local` from this revision; the `navi-edge` Worker is untouched by v0.6.9 and still runs the v0.6.8 build until a `wrangler deploy` says otherwise.

## Honest limits

- With `reuseExistingServer: true`, a foreign HTTP process that already serves the suite's dedicated port 4174 would be adopted as the webServer by Playwright's probe; the suite tells it apart only through the fixed port being dedicated. The refusal path is exercised for *other* ports, where the probe never comes into play.
- The reclaim matches on the command line of the pid `lsof`/`ss` reports. A dev.mjs started under a wrapper whose `ps` output does not name `scripts/dev.mjs` would be treated as foreign and refused, not killed.
- On a host with neither `lsof` nor `ss`, `listenerPids` returns empty, which is read as "unblocked" and the bind attempt is retried once; the error surfaces a step later with the same pointed message if the port really was held.
- Native amd64 container execution is produced by CI, and was not observed on this arm64 host.
