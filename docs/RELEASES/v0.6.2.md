# Navi v0.6.2

Tag: **`v0.6.2`** — annotated, pointing at the commit on `main` whose `reports/release-verification.json` records the run described below.
Package: `navi-interaction-bridge@0.6.2`, `AGPL-3.0-or-later`, published configuration `access: public` with `--provenance` through keyless OIDC Trusted Publishing.

v0.6.2 is the monetization milestone. v0.6.1 made the delivered runtime provable; what the deployment could not yet do was treat a tenant as a customer with boundaries and a plan. This release enforces both: a tenant may name the origins its pixels may report from, and it may be sold a number of ingested events per window that is counted durably rather than in one process's memory. The same contract is enforced on the self-hosted server and on the Cloudflare Worker, and the operator gets a scraped view of every window.

## Provenance

The receipt is published by the commit that carries it, so `evidence.revision` is always one step behind the tag. `evidence.sourceTree` closes that gap: it is a digest over every tracked path outside `reports/`, taken at the gate's revision, and the publish preflight's `provenance-parity` check refuses to proceed unless the tagged tree carries that same digest — or is that revision with nothing outside `reports/` changed.

The digest itself is not repeated here on purpose: a tracked file cannot state the digest of the tree that contains it. The authoritative values are the ones the gate recorded — `evidence.sourceTree` in [reports/release-verification.json](../../reports/release-verification.json) and the same digest printed in the generated [release notes](../../reports/release-notes.md) — and the check that matters is the one the preflight runs against the tagged tree.

## Upgrading

- **Existing tenants keep working.** Without `allowed_origins` and without a ceiling, a tenant is unrestricted and unmetered — the behaviour it had before this release. Enforcement is opt-in per tenant or by the deployment-wide `NAVI_MAX_EVENTS_PER_WINDOW`.
- **A window is durable, so a restart no longer refunds it.** The count lives in the store the deployment already mounts; an operator who wants to refund a tenant deliberately deletes that tenant's `tenant_quotas` row rather than restarting the service.
- **`GET /metrics` can be locked down without touching probes.** Set `NAVI_METRICS_TOKEN` and point the scraper at it with a bearer credential; `/healthz` is deliberately not behind that token.
- **The Worker needs three columns.** Apply `allowed_origins`, `max_events_per_window`, `window_seconds`, `window_start_ms` and `event_count` to `sites` before deploying the Worker, or make the PostgREST `select` visible to the service role; a site with a null ceiling stays unmetered.
- **Version.** `package.json` and the lockfile are `0.6.2`. The Navi protocol stays `0.3.0` and the MCP revision `2025-11-25`: neither changed.

## Honest limits

- **The Worker's counter is a read-modify-write.** Two isolates accepting events for the same site in the same instant can both read the same `event_count`, so a burst can overshoot by the number of concurrent requests. The ceiling is enforced, not atomically reserved; a Durable Object or a Postgres function is where that atomicity belongs.
- **Quota is per store, not per fleet.** The self-hosted window is durable within one store file, which is one writer by design; two replicas with two stores meter separately. The shared edge — the Worker's row — is the place a fleet-wide ceiling is enforced.
- **The amd64 leg has not been observed here.** It is configured, statically validated and required by the publish gate, but it runs on GitHub's x86_64 runner and the receipt it writes is produced there.
- **Nothing is deployed by this note.** No image is pushed; the publish is the npm tarball and its provenance attestation.
