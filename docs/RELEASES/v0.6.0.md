# Navi v0.6.0

Tag: **`v0.6.0`** — annotated, pointing at the commit on `main` whose `reports/release-verification.json` records the run described below.
Package: `navi-interaction-bridge@0.6.0`, `AGPL-3.0-or-later`, published configuration `access: public` with `--provenance`.

v0.6.0 is the operability milestone. The bridge and the host service already worked; what they could not do was tell an operator what they were doing, keep their own journals from growing, or stop cleanly — and the SQLite store the deployment guide promised was unreachable on the exact runtime the image pins.

## Upgrading

- **The store backend follows the file.** A deployment already writing the append-only JSONL log at `/data/telemetry.db` stays on the log: the store reads the first sixteen bytes of an existing file, and only a file that already carries the SQLite header is opened as a database. There is no automatic migration, and this is deliberate — reading a log as a database fails its first statement, and reading a database as a log answers with an empty audit trail instead of an error. New deployments, and deployments whose volume already holds a database, get SQLite in WAL mode.
- **`-wal` and `-shm` now exist beside the store file.** Mount the directory, as both shipped deployment files already do; a checkpoint at teardown folds them back in, and mounting the single file would lose whatever was only in the sidecar.
- **`--experimental-sqlite`** is set by the image and both compose files. On Node 22.13 and newer it is a no-op, because `node:sqlite` was unflagged there ([nodejs/node#55890](https://github.com/nodejs/node/pull/55890)); it is load-bearing only on 22.5–22.12, and it is legal in `NODE_OPTIONS` on both lines. The module still emits an `ExperimentalWarning` at startup — accurate, not suppressed, and harmless to the health check.
- **Version.** `package.json` and the lockfile are `0.6.0`. The Navi protocol stays `0.3.0` and the MCP revision `2025-11-25`: neither changed.

## Honest limits

- **No latency histogram exists.** The dashboard's throughput panel is the closest available signal and says so in its own description; a p99 cannot be computed from what is exported.
- **No process-start or exit-code series exists**, so `NaviUngracefulShutdown` infers restarts from repeated counter resets. It can see that the service keeps coming back, not why it left; the exit code is in `docker inspect`, not in a metric.
- **The metrics are per process.** Two replicas behind one address each keep their own counters and their own token buckets, so a fleet-wide rate limit or a fleet-wide total is still the shared edge's job.
- **The alerting files are validated, not exercised.** `npm test` parses them as the tools that will read them, and holds every expression against the metric names the running services declare — but no rule has ever fired in production, because there is no production.
- **Node 24 is not the pinned runtime.** The release gate requires Node 22.x and this release was verified on 22.23.3, the base the image pins; the suite also passes on Node 24.21.0, which is what the development machine runs.
