# Navi v0.6.6

Tag: **`v0.6.6`** — annotated, pointing at the commit on `main` whose `reports/release-verification.json` records the run described below.
Package: `navi-interaction-bridge@0.6.6`, `AGPL-3.0-or-later`, publish configuration `access: public` with `--provenance` through keyless OIDC Trusted Publishing (`environment: release`, `id-token: write`, npm ≥ 11.5.1).

v0.6.6 finishes the structural modularization v0.6.5 began. `server/index.js` came down to 515 lines there; `server/store.js` was the last file in `server/` above the repository's 1,000-line ceiling at 1,282, and it is now 85 lines over five modules that each own one job: the SQLite WAL backend, the append-only JSONL backend, the record shapes both share, backend detection, and the process-lifecycle sentinels. Nothing about the store's behaviour changed — the transaction in `applyWebhookEvent`, the quota window, the one-time checkout claim, the retention prune and the compaction that preserves violation ids are byte-for-byte the code that shipped in 0.6.5, moved into files where they can be read. The release also publishes, for the first time, the Edge schema-version diagnostic that 0.6.5 recorded as a post-release follow-up on `main`.

## Upgrading

- **No schema change.** `deploy/supabase-schema.sql` is unchanged in this release. A deployment that already applied the 0.6.5 schema needs nothing; one coming from 0.6.4 or earlier should apply it before deploying the Worker, because the Edge diagnostic in this package reports a missing `apply_stripe_webhook` signature as a `503` rather than provisioning against it.
- **No store migration.** The split is source layout only: the same file, the same tables, the same JSONL lines, the same discriminators. An existing `/data/telemetry.db` or JSONL log is opened by the same backend it was written by, and `storeFormat` still decides that from the file's bytes.
- **Nothing to reconfigure.** No environment variable, route, status code, header, body or claim TTL changed. `NAVI_STORE`, `NAVI_RETENTION_DAYS`, `NAVI_MCP_STATE_FILE` and the quota variables mean what they meant in 0.6.5.
- **Version.** `package.json` and the lockfile are `0.6.6`. The Navi protocol stays `0.3.0` and the MCP revision `2025-11-25`: neither changed.

## Honest limits

- **The split is a move, and the suite is the proof of that.** Every route the tests exercise behaves as it did; a header or a log line that no test observes could still have changed in transcription, which is the residual risk of any extraction this size.
- **The two backends are still one file each at 339 and 510 lines.** They are under the ceiling and cohesive, not small. `store-log.js` is the larger of the two because compaction, the append queue and the ledger reads share one serialization rule; splitting it further would separate code that must run under the same lock.
- **`node:sqlite` remains Stability 1 on the Node 22 line.** The warning at startup is unchanged and still deliberate.
- **The amd64 leg has not been observed here.** It is configured, statically validated and required by the publish gate, but it runs on GitHub's x86_64 runner and the receipt it writes is produced there.
- **Nothing is deployed by this note.** No image is pushed and no service is restarted; the publish is the npm tarball and its provenance attestation.
