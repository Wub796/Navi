# Navi Protocol v0.3 acceptance criteria

## Scope and artifact paths

Refactor `src/navi.js`, `types/navi.d.ts`, `demo/index.html`, `tests/navi.spec.mjs`, `docs/AGENT-INTEGRATION.md`, and `README.md`. Produce `dist/navi.min.js` with **strictly <15,000 raw UTF-8 bytes**, no runtime dependencies or source maps. Save reproducible size, tick duration, long-task and completeness metrics in `reports/verification.json` and summarize in `reports/VERIFICATION.md`. Backend remains an architecture plan, not an implemented service. No public deployment is authorized.

## Versioned public API

- `version: '0.3.0'`.
- `ready(): Promise<void>` waits for the current discovery/classification/mutation queue to drain. Initial API presence does not imply readiness. Work settles across idle/frame ticks.
- `refresh(): Promise<void>` enqueues full rediscovery, not a synchronous scan. Automatically intercept newly attached roots without requiring refresh.
- `actions({limit?: number}): Promise<{version, truncated, actions: Action[]}>` waits for indexing and computes fresh state in **time-sliced** batches. Bounded limit 1..5,000 (default 500). No selectors/HTML or values in the action dictionary.
- `execute(targetId, actionType, payload?): Promise<{target_id, action, dispatched: true}>` resolves exactly one live target through the private index (including captured closed roots and same-origin frames). Supported actions: `click`, `type` with `{text}`, and `select` with `{value}`. Checks visibility, enabled state, viewport intersection and center-point hit testing immediately before dispatch. Rejects missing/ambiguous/unsupported/unavailable targets, invalid payloads, concurrent execution, and stopped instances. It focuses native controls, uses native value setters for controlled inputs, emits realm-correct key/input/change events, and awaits two animation frames plus indexing. A dispatched event is not proof of business success or trusted user input.
- `stats()` reports cumulative generated tags, scanned elements, current live root/index counts, pending work, tick durations (bounded samples), maximum/over-budget ticks, and initial elapsed time. `stop()` cancels pending scheduler jobs, observers/listeners, restores owned shadow hooks, rejects waiters and releases strong references. Re-injection stays a no-op.

Action format:

```json
{
  "target_id": "checkout-submit",
  "role": "button",
  "name": "Complete Purchase",
  "state": {"is_visible": true, "is_enabled": true, "is_in_viewport": true, "is_occluded": false},
  "coordinates": {"x": 450, "y": 820, "width": 120, "height": 40},
  "suggested_action": "click"
}
```

Coordinates default to CSS pixels relative to the target's **own document viewport**, not global screen coordinates. Optional `coordinateSpace:'top'` converts same-origin offsets/borders for trusted driver fallback; optional `viewportOnly:true` returns only intersecting controls. `data-navi-trusted="true"` yields an explicit `success:false`, `untrusted_gesture_required`, `dispatched:false` pre-dispatch response. See [competitive benchmark acceptance](BENCHMARK-ACCEPTANCE.md) for extended measurement and fallback rules. Occlusion includes shadow-boundary retargeting and containing same-origin iframe hit tests; transformed frames use a conservative blocked result. Center-point hit testing is an approximation, not universal actionability. Do not auto-scroll or force-click; an executor may safely scroll separately and rediscover.

## Distribution (package 0.4.0)

The protocol stays 0.3.0. Packaging adds:

- `dist/navi.min.js`: self-executing IIFE for `<script>`/CDN injection, strictly **<15,000 raw UTF-8 bytes**.
- `dist/loader.min.js`: the tenant embed snippet, strictly **<700 raw bytes**, configured only by attributes on its own tag (`data-key`, `data-sri`). It injects the bundle asynchronously from `/v1/navi.js?key=…` resolved against the loader's own origin, appends the published `integrity` hash plus `crossorigin="anonymous"`, and fails closed (every queued call rejects) when the key is refused or the hash does not match. The 71-byte hash travels in the embed tag rather than inside the snippet, because baking it would push the snippet past its budget; `npm run build` prints the exact tag with the current hash, and enforcing the budget is a build failure, not a warning. It also injects the page-side discovery marker `<meta name="agent-bridge" content="active" data-version="…">`, whose `data-version` is read from the SDK that executed rather than hardcoded, so a page that failed to load its bundle advertises the marker with no version instead of a version it is not running.
- Before the bundle executes, `window.Navi` is a deferred stub (`Navi.stub === true`, `version '0.0.0'`) whose every call is queued and resolved with the real result, so `await Navi.actions()` written above the SDK behaves identically. The shipped bundle must recognize that stub and install over it (any other pre-existing `Navi` is left alone), and must not gain bytes beyond the budget for doing so.
- `dist/index.mjs`, `dist/index.cjs`, `dist/index.d.ts`: ESM and CommonJS exports of `NaviPlaywrightAdapter`, `naviAdapter`, `validateFlow`, `runFlow`, `installNavi`, `connectNavi`, `naviSdkPath`, `NAVI_PROTOCOL_VERSION`, plus the client-side SDK types (`NaviAPI`, `NaviAction`, `NaviActionMap`) re-exported from the package entry. Both module builds must resolve the shipped `navi.min.js` at runtime, and the `./navi.min.js` subpath must have a `types` condition pointing at `dist/navi.d.ts`.
- `bin/navi-agent.js` (`navi` bin): `navi run --url <url> --action-file <flow.json>` and `navi discover --url <url>`, with `--timeout`, `--viewport`, `--headed`, `--json`, `--report`, `--discover`, `--strict-synthetic`, `--allow-consequential`, `--quiet`.
- Flow documents are untrusted input: bounded size, strict unknown-key rejection, prototype-key rejection, no `eval`, and no implicit scrolling. Steps marked `"consequential": true` require `--allow-consequential`. Failed and timed-out steps are reported and **never retried**, because they may already have applied.
- Only `http(s)` URLs without embedded credentials are opened. Exit codes: 0 success, 1 flow/assertion failure, 2 usage/invalid flow/blocked consequential step, 3 environment failure.
- `bin/navi-mcp.js` (`navi-mcp` bin): a standalone Model Context Protocol server on **stdio**, using newline-delimited JSON-RPC 2.0. It must ship with **zero runtime dependencies** and expose exactly five tools:
  - `navi_navigate` — open an http(s) URL, read the host's agent-bridge marker (the `Link: rel="agent-bridge"` response header, or the loader's `<meta name="agent-bridge">` tag, which wins when both are present), then negotiate the runtime: read the host's own discovery document from the page origin inside a 500ms budget, inject the asset its `endpoints.script` designates, verifying a declared `integrity` hash before any of those bytes executes, bind to a Navi instance the page is already running instead of injecting a second copy, and otherwise fall back to the packaged runtime. It reports the install strategy (`already-present`, `tag` or `evaluate`), `sdk.source` (`host_manifest`, `host_inline` or `bundled_fallback`), a `runtime_resolution` object and a `discovery` object (`instrumented`, `source`, `declared_version`, `manifest`, `script`, `integrity`). `runtime_resolution` is the field a receipt reader should prefer: `strategy` is the same value as `sdk.source`, derived from the same runtime decision through the frozen `RESOLUTION_STRATEGY_MAP` (`page` → `host_inline`, `host_manifest` → `host_manifest`, `bundled` → `bundled_fallback`) that `navi_navigate` also uses to derive the receipt field, and `assertResolutionParity` compares the two derivations before the receipt is returned — a divergence fails the call with `NAVI_RESOLUTION_DIVERGED` (or `NAVI_RESOLUTION_UNMAPPED` for a decision the table does not carry) rather than returning a receipt that contradicts itself, `manifest_url` names the discovery document that was actually read and is `null` when none was — `discovery.manifest` reports the *advertised* URL even when the fetch never happened — and `script_origin` is `host` or `bundled`, naming whose build is running. It exists because `source` alone is ambiguous in an envelope that also carries the manifest's `source` (the host's Corresponding Source URL) and `discovery.source` (how instrumentation was detected). A negotiation that cannot complete warns with `UNINSTRUMENTED_HOST`, `MANIFEST_UNREACHABLE`, `MANIFEST_CROSS_ORIGIN`, `MANIFEST_INCOMPATIBLE`, `HOST_ASSET_MISMATCH` or `HOST_ASSET_BLOCKED` and still automates the page: refusing to drive a page because its metadata was unusable would be worse than saying plainly which build produced the map. The document is only ever read from the page's own origin (enforced again across redirects) and its asset only from a URL that document names, so a hostile page cannot turn the agent's network into a fetcher for arbitrary hosts.
  - `navi_get_actions` — return the action map, viewport-filtered by default with `all: true` for the whole document. An optional `since_version` cursor returns only what changed since that version; `reset: true` means the reply is a full map that replaces the caller's cache. See [differential action maps](AGENT-INTEGRATION.md#differential-action-maps).
  - `navi_execute_action` — `target_id` + `action_type` (`click`/`type`/`select`) + optional `payload`, through the same guarded adapter the CLI uses, including the trusted native-coordinate fallback for `data-navi-trusted="true"` controls. It also accepts an optional `settle` request (`wait_for`, `timeout_ms`) and answers with the receipt `{ executed, settled, elapsed_ms, final_url }` when one was requested.
  - `navi_assert_state` — assert existence, visibility, enabled/in-viewport state and expected accessible name for a target.
  - `navi_set_session` — hydrate cookies and localStorage before navigating (inline payload or `storageState.json` path).

### Deterministic settlement

An action returns when it is dispatched, which is not the moment the page has reacted. `navi_execute_action` and `NaviPlaywrightAdapter.execute()` therefore accept an optional settlement request — `{ wait_for: 'mutation_settle' | 'navigation' | 'target_hidden', timeout_ms }` (defaults `mutation_settle`, 3000ms; `timeout_ms` must be an integer in 1…30000).

- `mutation_settle` holds when the document, its open shadow roots and its same-origin frames record no DOM mutation for at least 100ms. Observation is armed *before* dispatch, so a mutation made during the click counts.
- `navigation` holds when the top-level URL changed or the document reloaded. A reload that destroys the execution context mid-dispatch is treated as the receipt rather than surfaced as a transport error, because the navigation is the evidence the action applied.
- `target_hidden` holds when the dispatched target is no longer in the action map, or Navi reports it invisible or occluded. A truncated map cannot prove absence, and is therefore never read as "hidden".
- Receipts are honest in both directions: a condition that never holds returns `settled: false` with `reason: 'timeout'` while still reporting `executed: true` and the dispatch, and the action is never retried or re-reported as failed because settlement did not hold. An invalid request returns `INVALID_SETTLE` **before** anything is dispatched. A call without a `settle` request carries no receipt fields at all, so it cannot be mistaken for a verified one.
- Scope limit, documented rather than hidden: settlement is a scheduling signal, not proof of completion. A mutation inside a *closed* shadow root is invisible to the driver, `target_hidden` trusts Navi's own state, and `navigation` can be satisfied by a same-page redirect. Nothing here proves a network write or a server-side transaction finished.
- Every tool result is the structured envelope `{ content: [{ type: "text", text: JSON.stringify(payload) }], isError: boolean }`. Refusals must be actionable, distinguishing `NOT_FOUND` (re-read the map; ids change with re-renders), `UNAVAILABLE` (hidden, disabled, off-screen or occluded) and `INVALID_URL` (never echoing embedded credentials), and must carry the underlying adapter error code.
- Diagnostics go to stderr only; stdout is reserved for the JSON-RPC stream. `--version` and `--help` work without a browser.
- **Scope limit:** MCP tool calls are not gated by `--allow-consequential`. An agent holding this server can dispatch a consequential control, so the server is not an authorization boundary. Reviewed flows with that gate remain the CLI's job; the README states this plainly. `--no-fallback` narrows the session further: trusted-input controls are refused with `FALLBACK_DISABLED` instead of being driven by real mouse and keyboard input, and that refusal is covered by a test rather than only documented.
- Publishing to a registry is out of scope; `package.json` is publish-ready but no release is made.

## Remote transport and session hydration (package 0.4.0)

- `navi-mcp --transport stdio|sse` selects the transport; stdio remains the default. `--transport sse --port <port> --host <host>` defaults to `3001` and `127.0.0.1`, and an invalid port is a usage error (exit 2) rather than a crash.
- The SSE binding is implemented with `node:http` only — no HTTP framework, router, or SSE dependency — and exposes `GET /sse` (event stream whose first frame is `event: endpoint` carrying the same-origin POST URL), `POST /message?sessionId=<id>` (one JSON-RPC message, acknowledged `202` before the work happens, reply delivered on the stream), and `GET /healthz`.
- Each SSE connection owns its own browser session, so one client cannot act on another's page. An unknown or expired `sessionId` is a `404` JSON-RPC error naming the recovery step, not a silent drop.
- The remote transport is **bounded**, because an open SSE port is an open browser. `GET /healthz` reports the live posture (`sessions`, `maxSessions`, `auth`, `idleTimeoutMs`). With `--auth-token <token>` (or `NAVI_MCP_TOKEN`), both `/sse` and `/message` require `Authorization: Bearer <token>`, compared in constant time; a missing, wrong or unschemed credential is `401 UNAUTHORIZED` with a `WWW-Authenticate` challenge, decided *before* the session is looked up so an anonymous caller cannot probe for live session ids, and the credential never appears in a response body or a log. `--max-sessions <n>` (default 10) answers a stream past the ceiling with `503 TOO_MANY_SESSIONS` and `Retry-After` without starting a session, and the count is live, so closing a stream frees a slot. `--idle-timeout <seconds>` (default 300; `0` disables) reaps a session that receives nothing for that long and closes its browser, while a session with a call in flight is never reaped. A `--host` that is not loopback with no token is **refused** with exit code `2`, not warned about; `--max-sessions` below 1, a non-numeric `--idle-timeout` and a valueless `--auth-token` are usage errors (`2`).
- stdout stays a clean protocol surface on both transports; diagnostics go to stderr. The transport is **not** an authentication boundary: session ids are anonymous by design and the server must be bound to loopback or fronted by an authenticating proxy.
- `navi_set_session` is the fifth tool. It accepts an inline `{ cookies, origins }` payload or a path to a Playwright `storageState.json` file (and may open `url` in the same call). Cookies require `name`, `value` and either `url` or `domain`+`path`; origins must be bare http(s) origins with a `localStorage` array of `{ name, value }`; unknown keys, a non-existent path, a malformed shape, or a state that would hydrate nothing are refused with `INVALID_SESSION` and actionable text.
- Hydration rebuilds the context instead of patching a live document, because localStorage only applies at document start. Cookie and storage values never appear in a response, and a refused call must leave the existing session usable.

## Host service: distribution, ingestion and the tenant loader (package 0.4.0)

`server/` is a standalone `node:http` service with no runtime dependencies:

- `GET /v1/navi.js?key=<tenant_key>` serves the built bundle with `Cache-Control: public, max-age=3600, stale-while-revalidate=86400`, an `ETag` equal to the quoted SHA-384 from `dist/sri.txt`, `Content-Type: application/javascript`, `Vary: Accept-Encoding` and `nosniff`; `If-None-Match` yields `304`; a missing or unknown key yields `401 UNAUTHORIZED`; a missing bundle yields `503 SCRIPT_UNAVAILABLE`. The served bytes must equal `dist/navi.min.js` exactly.
- `GET /v1/loader.js` serves `dist/loader.min.js` unmodified, with the same cache policy. It carries no tenant key of its own: the loader reads `data-key` from its embed tag and appends it to the bundle request, where it is checked.
- `GET /.well-known/navi.json` is the public agent discovery document, and the one JSON response this service lets a shared cache keep (`public, max-age=300, stale-while-revalidate=3600`, a strong `ETag`, `304` on `If-None-Match`). Its body is exactly `{ version, protocol, status, capabilities, endpoints, source }`: `version` must equal `NAVI_PROTOCOL_VERSION` in `src/adapter.js` and the literal in the served bundle, `protocol` must equal `PROTOCOL_VERSION` in `src/mcp/server.js`, `status` is `ready` when both distributables are on that host and `degraded` when they are not, `capabilities` is the three implemented behaviours, `endpoints.script` must be a path that really serves `dist/navi.min.js` byte for byte, `endpoints.mcp_sse` comes from `NAVI_MCP_SSE_URL` (loopback by default), and `source` at the top level is the Corresponding Source this host offers: the same URL `GET /v1/source` redirects to, and the same override. Deliberately unauthenticated: it names only public paths and the endpoint an operator chose to publish.
- `GET /v1/source` answers `302` with `Location: https://github.com/Wub796/Navi`, which is the offer AGPL-3.0 section 13 requires of this service: a network service must offer the Corresponding Source of the version that is actually running to the users who interact with it, through a standard means, at no charge, and readable without identifying yourself, because an offer a reader must authenticate to receive is not an offer to the users of the service. It is public metadata, so it carries the discovery document's cache policy, and any method other than `GET` (or `HEAD`) is `405 METHOD_NOT_ALLOWED`. `NAVI_SOURCE_URL` — or the `sourceUrl` host option — points both this redirect and the document's `source` field at another repository, which is what a host running a modified version is obliged to do: upstream's repository does not discharge section 13 for a fork.
- Every response — including `404`, `405`, `304` and the `302` from `/v1/source` — carries both relations in one `Link` header value: `</.well-known/navi.json>; rel="agent-bridge", <https://github.com/Wub796/Navi>; rel="source"`. The first means discovery never depends on a hard-coded path, and the document itself is reachable by following that relation from any other route; the second is the source offer AGPL-3.0 section 13 requires of a network service. Both are set on the response before routing rather than in each route, so a route added later cannot omit either. RFC 8288 allows several comma-separated entries and the reader that follows `rel="agent-bridge"` splits them, so the second relation does not disturb the first.
- Both scripts are served with `Access-Control-Allow-Origin: *`, because the supported embed is a `crossorigin="anonymous"` script carrying an `integrity` hash, which the browser fetches in CORS mode and verifies before executing. The bytes are public and tenant-keyed, so the wildcard exposes nothing a plain `<script>` tag did not already expose. An embed from a non-loopback page origin to a loopback host is blocked by Chromium's Private Network Access policy, which is why the loader suite serves its fixture from a loopback origin.
- `POST /v1/telemetry` accepts `{ tenant_id, url_origin, actions_indexed, actions_executed, execution_failures }` as `application/json` or as the `text/plain` shape `navigator.sendBeacon(string)` produces, and nothing else. Exactly those five keys; counters are integers in `0…1_000_000`; `tenant_id` must be a registered tenant; `url_origin` must be a canonical origin (no path, query, fragment, trailing slash or embedded credentials). Rejections are `400 INVALID_PAYLOAD`, `401 UNKNOWN_TENANT`, `413 PAYLOAD_TOO_LARGE` (hard 2 KB cap, enforced against both the declared length and the stream) or `415 UNSUPPORTED_MEDIA_TYPE`, each with a message naming the field and the rule. Raw DOM/HTML text is rejected and never persisted.
- `GET /v1/telemetry?key=<tenant_key>` returns that tenant's aggregate; tenant-scoped responses are `Cache-Control: no-store`.
- Aggregates persist through Node's built-in `node:sqlite` when the runtime provides it — importable without a flag from Node 22.13, and the pinned image also passes `--experimental-sqlite` for the 22.5–22.12 window — and otherwise through an append-only JSONL log at the same path, so the store also works on a runtime where that built-in module is not importable; `store.mode` reports which is live, and both modes must produce identical summaries.
- **The store file decides the backend, in both directions.** Both backends share one path, so an existing non-empty file without the SQLite magic header keeps the log backend even where SQLite is available (reopening an operator's log as a database fails its first statement with `SQLITE_NOTADB`, and reinterpreting a database as a log would answer with an empty audit trail instead of an error), a file that carries the header keeps SQLite, and a runtime that cannot import `node:sqlite` **throws a named, actionable error** rather than degrading a database to an empty log. A new or zero-length path is served by SQLite when it can be. `tests/node22-sqlite-container.spec.mjs` asserts all of it, including the refusal in a child process started with `--no-experimental-sqlite`.
- **Operational config is artifact-checked.** [deploy/prometheus/alerts.yml](../deploy/prometheus/alerts.yml) must parse as YAML, define uniquely named rules in named groups, give every rule an `expr`, an actionable `summary` and `description`, and a `severity` from the routing set; no rule may compare a counter without `rate`, `increase` or `resets` (the alert that fires forever after one event); the named rules the runbook refers to must exist; and every `navi_*` series any rule reads must be declared by one of the two live expositions. [deploy/grafana/dashboard.json](../deploy/grafana/dashboard.json) must parse, carry a `uid`, a `schemaVersion` and a datasource template variable every panel binds to, give each panel a unique id, a title, a description and at least one target with a `refId`, and read only series the services declare. Both are asserted by `tests/ops-alerting.spec.mjs`, which scrapes the real `/metrics` endpoints to get the names rather than trusting a list.
- Tenant keys come from `NAVI_TENANTS` (`key:tenantId,…`). The built-in `dev-tenant-key`/`demo-tenant` pair is a documented local development value, **not** a secret, and must not be used in production.
- **The store is pruned, and the window is visible.** `pruneViolations({ max_age_days, tenant_id })` deletes expired violations for one tenant or all of them; `NAVI_RETENTION_DAYS` (default 30, `0` disables) sweeps at startup and every six hours, off the request path. Refused rather than obeyed: a window of zero, negative, `NaN` or above 36,500 days, because an unparseable SQLite date modifier deletes nothing while looking like it succeeded. SQLite compares as Julian days, since the stored ISO-8601 `T` sorts above the space in SQLite's own `datetime()` output and a text comparison would spare every row on the cutoff's day. `GET /healthz` reports `retention_days` so a disabled sweep cannot pass as an enabled one.
- **Log compaction is atomic and does not renumber.** Line by line to a temporary file, then renamed over the original: a reader sees the old file or the new one, never a mixture, a failed rewrite leaves the original intact, aggregates are copied verbatim, and surviving violations keep the id a reader already holds for them, with a `navi_store_meta` line carrying the highest id ever issued so the next append continues past it across a restart. Mutations are serialized in-process, so an append lands either before the rewrite or after it.
- **`POST /v1/tenants/<tenant_id>/maintenance/prune`** deletes the authenticated tenant's expired records and answers `{ ok, tenant_id, max_age_days, pruned_count, remaining_count }`. Bearer key only, `403` for another tenant's path, `400` for an out-of-range or non-integer `max_age_days` / unknown field / malformed body, `415` and `413` as elsewhere, and the default window is the configured retention (never `0`, which would prune nothing while reading as "everything"). Pruning one tenant provably leaves another's records intact.
- **Ingestion is capped per tenant on both ingest routes.** A token bucket of `120` requests per minute with a burst of `30` (`NAVI_RATE_LIMIT_PER_MINUTE`, `NAVI_RATE_LIMIT_BURST`, `0` disables) answers `429 RATE_LIMITED` with `Retry-After` (whole seconds, floor 1), `X-RateLimit-Limit` and `X-RateLimit-Remaining: 0`, and stores nothing for it; accepted responses carry the same counters. A key-authenticated request is charged before its body is read and an unauthenticated beacon after its payload names a tenant, so a malformed beacon stays a `400`; one tenant's burst never spends another's allowance, and idle buckets are forgotten after ten minutes so the map tracks active tenants rather than every tenant ever seen.
- **`GET /metrics` is a Prometheus document, not a JSON one.** `text/plain; version=0.0.4; charset=utf-8`, `no-store`, `nosniff`, unauthenticated like `/healthz` and aggregate-only like the MCP exposition: `navi_host_requests_total{route,status}` (counted when a response finishes, so a refusal is counted too), `navi_host_rate_limited_total{tenant_id}`, `navi_host_prune_events_total`, `navi_host_pruned_records_total`, `navi_host_active_tenants`, `navi_host_store_bytes`. The `route` label comes from a closed set — an unmatched path is the single series `route="other"` — so a scanner cannot mint a label per path it tries, and no series carries a URL, a tenant key or a session id. The label-free aggregates and both gauges are present from the first scrape, so an alerting query has a series before any traffic arrives; a `POST` to the route is `405`.
- **SQLite runs in WAL mode with `synchronous = NORMAL`.** `journal_mode` is recorded in the file and is asserted through an independent connection; `synchronous` is a property of one connection and is therefore read back from the store's own (`store.pragmas`), never restated. `auto_vacuum = INCREMENTAL` is set **before** the journal switches to WAL: with WAL already on, SQLite accepts that pragma and ignores it, so the ordering is asserted rather than assumed, and a file created by an earlier version keeps its own mode (VACUUM is the operator's tool for that).
- **A prune that removed rows checkpoints the journal, and a clean close removes its sidecars.** `store.checkpoint({ truncate: true })` runs `PRAGMA wal_checkpoint(TRUNCATE)` after any scheduled or on-demand prune that deleted something and again during teardown, so the `-wal` file an operator measures is the file that actually shrank; `{ truncate: false }` runs `PASSIVE` instead, a best-effort checkpoint is not allowed to turn a successful prune into a failure, and the log backend answers the same call with `{ busy: 0, log: 0, checkpointed: 0 }` so no caller branches on the backend. After `close()`, neither `-wal` nor `-shm` exists.
- **Shutdown is bounded on both services.** On `SIGTERM` or `SIGINT` the host stops accepting, drains in-flight requests for a strict **5 seconds** (`SHUTDOWN_DEADLINE_MS`, the same constant the MCP transports declare, asserted equal), destroys whatever is still open when that deadline passes, clears the retention interval, checkpoints and closes the store, and exits `0` — with the accepted writes still readable after a reopen and no journal or lockfile left behind. A half-open request that is neither idle nor finished is what proves the deadline is a deadline. Each handler is removed once it fires, so a second signal reaches the default action instead of waiting out a stuck drain. The MCP service does the same over both transports: signal or closed stdin, join the in-flight tool call within the same deadline, then close every session — which terminates its browser and removes its `navi-downloads-*` directory.
- Out of scope and documented as such: user authentication, quotas and billing, a limiter shared across replicas, deduplication, TLS termination, and any dashboard.
- **The client SDK must not gain telemetry.** `dist/navi.min.js` stays strictly under 15,000 bytes and keeps its verified no-network behaviour; the beacon is the hosting page's or tenant snippet's job, which the demo fixture demonstrates.

## Enterprise security (package 0.4.0)

### Strict CSP compliance

The shipped `dist/navi.min.js` must evaluate and run unmodified under `Content-Security-Policy: default-src 'self'; script-src 'self'; style-src 'self'`. Concretely:

- No `eval()`, no `Function` constructor, no `document.write`, no `insertAdjacentHTML`, no `<style>` element creation and no element `style` attribute writes anywhere in the bundle. This is enforced at build time by a forbidden-pattern scan that **fails the build**, and re-checked by the compliance suite against the served bytes rather than the source.
- Loading the bundle from the page origin and driving a real flow must produce zero `securitypolicyviolation` events and zero CSP-refused requests.
- A page whose policy blocks script injection must fail the install with a documented, actionable error (serve from the page origin, add a matching nonce, or use the `evaluate` strategy), never a silent no-op.
- The evaluator install strategy is allowed to work under a strict policy precisely because driver evaluation is not subject to the document's CSP; this is documented as the supported path rather than presented as a policy bypass.

### Defensive prototype isolation

Navi must cache the DOM primitives it depends on at initialization, in a closure, so that a host application that later replaces, wraps, nulls or freezes them cannot bend discovery or execution:

- Pinned set: `document.createElement`, `Element.prototype.getBoundingClientRect`, `Element.prototype.attachShadow` (plus its original/wrapper identity for ownership checks), `Element.prototype.matches`/`closest`-class traversals, `window.getComputedStyle`, `document.elementFromPoint`, `document.createTreeWalker`, `MutationObserver`, `IntersectionObserver`, `requestIdleCallback`, `requestAnimationFrame` and `queueMicrotask`.
- Freezing must not break startup: hook installation, identity comparison and restoration are guarded, so a frozen `attachShadow` yields a missing capability rather than a thrown exception during initialization.
- The isolation is verified adversarially, not asserted: geometry, computed style, occlusion hit-testing, execution and post-tamper mutation indexing must all still work after a host script poisons the prototypes, with zero uncaught page errors and zero calls reaching the poisoned primitives.
- Honest limit to retain in docs: a host that replaces `attachShadow` *after* Navi hooks it takes closed-root capture with it. Pinning cannot un-replace a function that was already swapped.

### Subresource Integrity

`npm run build` must write `dist/sri.txt` containing `sha384-<base64>` for the exact bytes of `dist/navi.min.js`, and the same value must appear in `reports/build.json` and `reports/verification.json`. The compliance suite re-derives the digest from the served bundle and fails on any drift, so the published integrity value can never describe a different artifact than the one shipped.

## Identity

Preserve developer `data-agent-target` verbatim. Use `data-navi-key` on a control or repeated-item ancestor for stable entity identity across sorting. Otherwise generate a semantic prefix plus **MurmurHash3** of landmark + tag + accessible-name approximation + sibling-relative position. No numeric allocation/collision counters. Stable-key identities omit sibling position; structural fallbacks necessarily change when identifying inputs change. Hash collisions/duplicate explicit IDs remain ambiguous and execution fails closed. Generated IDs update when identity inputs change (not Navi's own attribute writes). This is deterministic for identical inputs, not a guarantee of semantic identity on arbitrary sites.

## Traversal and lifecycle

Incremental TreeWalker traversal, no whole-document querySelectorAll in discovery/action maps; MutationObserver records processed in scheduler chunks; self-tag writes excluded. IntersectionObserver classifies intersecting candidates before background candidates; offscreen candidates deferred to subsequent idle ticks. Without IO all candidates use the deferred fallback.

Patch realm-local `Element.prototype.attachShadow` synchronously at initialization and on discovered same-origin frame documents. Preserve original mode/options/return value/exceptions. Store captured roots in WeakMap; support both open and closed roots. Closed roots created before interception (including parser-created declarative roots or early frame scripts) remain inaccessible. Roots/frame hooks/index entries for unmounted components are swept in incremental cleanup; weak element references and bounded tick samples avoid retaining detached control history. No perpetual strong collision registry.

## Performance verification

Cooperative scheduler aims for **≤6ms work per tick**, checks elapsed/idle budget between granular operations, uses a smaller internal budget for headroom, and caps operations per tick. Prefer requestIdleCallback with timeout, fallback to requestAnimationFrame followed by a microtask; schedule the next chunk as a new idle/frame callback (a microtask alone does not yield to rendering).

Measure 20 fresh-page runs with **10,000 fixture elements / 1,000 controls**, open/closed roots and a loaded same-origin iframe. Include initial indexing, rich metadata and mutation cleanup in SDK tick instrumentation; record raw tick samples, p95/max, elapsed completion and supported Long Tasks API entries during SDK activity. Gate measured max tick ≤6ms (therefore <16ms), **zero observed tasks >50ms**, complete indexing and correctness, and raw bytes <15,000. Record hardware/browser and compare prior ~49ms synchronous classification only as historical context (different work; not a 10× claim).

JavaScript cannot preempt a single native layout call, host event handler, browser GC or other scripts; universal hard frame/INP guarantees are impossible. Unsupported Long Tasks API is a verification blocker, not zero long tasks. Synthetic execute dispatch includes application handlers and cannot impose Navi's tick budget on the host application.
