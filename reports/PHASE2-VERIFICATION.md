## Task measurements

The latest complete table and raw trial values are generated by every suite run, including `verify:release`: [TCR-BENCHMARK.md](TCR-BENCHMARK.md) and [tcr-benchmark.json](tcr-benchmark.json). The pre-commit final suite completed **10/10 for both paths**, with 70 verified Navi settlement receipts across the ten tasks. Both paths use fresh Chromium browsers and alternate order on identical deterministic request-delay seeds.

Token figures are actual tokenizer counts of observation payloads, **not billed LLM usage**. These controllers autonomously execute a fixed semantic task policy; no generative planner/API is connected. The application is a realistic dynamic local sandbox, not an external production website. The report does not claim general agent intelligence, universal 100% reliability or a token advantage. Navi's richer MCP action maps cost more tokens than the compact Playwright ARIA snapshots in this task.

## Failures found and resolved

- The first benchmark run recorded Playwright 10/10 and Navi **9/10**. The failed Navi receipt carried the old review URL after an execution context was destroyed during navigation. The settlement cause was repaired, a focused regression added, and subsequent full paired runs passed. No failure was removed from an individual measured run, no retry added, and no assertion relaxed to claim success.
- Docker Desktop initially had no listening daemon, then restarted during the first browser download. A later full build succeeded; only a successfully exported and runtime-tested image is reported as valid.
- Omitting the compiler configuration from the Docker build context produced different SDK/SRI bytes. The build now copies the same configuration; runtime byte equality is asserted by the container test.
- The container validator initially had a JavaScript newline quoting error, then started an auxiliary fixture without awaiting readiness. Both validator defects were fixed (safe expression and bounded HTTP readiness check); the final 8/8 result is from the repaired script.
- Interactive preview exposed a fixture UX mismatch: selecting one item was valid in the UI but refused by the task-specific backend, and the review subtotal was hard-coded. The sandbox now accepts its offered quantity range and renders the selected quantity; the benchmark independently continues to require exactly two items and the correct $107.00 committed total.

## Production boundaries

- **Node 20 is EOL**; pinning it satisfies the requested runtime constraint, not current security support. Upgrade to a maintained LTS before production security signoff.
- **Chromium sandboxing is not enabled** by the existing Playwright launch default. Non-root, container seccomp and dropped capabilities do not replace browser-process sandboxing. This is a trusted authenticated worker posture, not a proven hostile multi-tenant isolation boundary.
- MCP still permits internal HTTP(S) destinations visible to the container. Require egress/SSRF restrictions, a TLS/auth proxy and a clear caller-trust policy before broader network exposure.
- No image vulnerability scan, Linux/AMD64 validation, hosted CI execution, external-site TCR or actual model-billed token benchmark was performed. Debian system package versions are not snapshot-pinned.
- Node 20 telemetry uses the JSONL store fallback. Retention, quotas, backup and future SQLite migration remain operator responsibilities.
